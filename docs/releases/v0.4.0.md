# CortexState 0.4.0

Shared, inspectable memory with an evidence-gated deployment learning loop for different models, harnesses, and skills.

## Packages

- `cortexstate-0.4.0` — Python memory engine, authenticated API, dashboard, deployment learning ledger, and portable Python ranker.
- `cortexstate-client-0.4.0.tgz` — JavaScript ESM client and TypeScript declarations.
- `cortexstate_rank-0.4.0` — optional native BM25 scorer. CI builds wheels for Python 3.10 and 3.12 on Linux, Windows, and macOS runners.
- Repository source archive for the matching release tag.

## Changes

- Record consent-asserted, redacted deployment outcomes with optional model, harness, skill, and application provenance.
- Tie candidate lessons to retained same-scope evidence. Store caller-supplied scorecards for baseline/candidate success, safety regressions, token use, and latency.
- Enforce held-out flag, no regression on recorded success/tokens/latency, zero reported safety regressions, and at least one strict gain before a lesson can be promoted.
- Require an explicit approval label. Provide candidate listing, rejection, revision-checked rollback, and deletion of evidence with derived lessons.
- Add a live dashboard view for outcome capture, candidate review, scorecards, and approved promotion.
- Keep model-weight training and benchmark execution outside CortexState. The evaluator and operator authorization are responsibilities of the deploying application.
- Add architecture, integration, API, package, and security documentation for the cross-stack learning path.
- Document an optional offline actor–writer RL integration for trainable policies; no trainer, reward model, rollout worker, or weight-update code is included.
- Include experimental, dependency-free reward shaping helpers for external RL trainers to score actor discovery, future-task memory utility, hard safety eligibility, and grouped advantages. Dedicated failure tests and a trainer are not included.

## Limits

This release does not run an evaluator, capture arbitrary agent traces, train model weights, or guarantee a candidate's scorecard. The caller supplies evaluation results and the `heldout` flag; the service enforces arithmetic gates but cannot verify evaluator independence, suite protection, statistical confidence, or truthful inputs. The static tenant-key API authorizes all operations within a tenant. Use a trusted backend to separate agent, evaluator, and reviewer permissions. See [continual improvement](../CONTINUAL-IMPROVEMENT.md), [API contract](../API.md), [security](../../SECURITY.md), and [capabilities](../CAPABILITIES.md).
